# Шаг 1б. Растения на полях: GPU-инстансинг

Код: `Assets/FarmSim/Fields/Runtime/Crops/`, `Shaders/CropCulling.compute`, `Shaders/CropInstanced.shader`.

## Как работает (каждый кадр)

```
FieldGrid (CPU) ──изменённые чанки──► _FieldStateTex (GPU)
       │
CropChunkIndex: какие чанки 32×32 м засеяны (пересчёт только изменённых)
       │
CropRenderer (CPU): видимые засеянные чанки (коробка в пирамиде камеры, ближе maxDistance), ближние первыми
       │  ≤ 192 чанков → буфер _VisibleChunks
       ▼
CropCulling.compute
  ClearCounters → CullStems (поток = кочка) → WriteArgs
  CullStems: клетка из _FieldStateTex → засеяно? культура? → дальность (прореживание) → пирамида камеры
             → 32 байта (позиция+поворот, высота/ширина/рост/флаги) в участок своей культуры
       ▼
Graphics.RenderMeshIndirect — один вызов на культуру, число стеблей CPU не знает
       ▼
CropInstanced.shader: масштаб по росту, ветер (верх гнётся сильнее), цвет молодое→спелое, цветение рапса, погибшее; тени
```

Комбайн срезал полосу, и пиксели текстуры поля поменялись. В следующем кадре этих стеблей уже нет, буферы на CPU никто не перестраивает.

## Что исправлено относительно присланного примера

| В примере | Что было бы | Как сделано |
|---|---|---|
| Ключевое слово `UNITY_PROCEDURAL_INSTANCING_ENABLED` включалось через `EnableKeyword`, без `#pragma instancing_options procedural:setup` | ветка с буфером не компилируется, все стебли рисуются в одной точке | буфер читается напрямую по `SV_InstanceID`, без ключевых слов |
| Шейдер на CG и `UnityCG.cginc` | не работает в URP | URP HLSL с проходами ForwardLit, ShadowCaster и DepthOnly: тени от растений и на растениях |
| Карта поля читается через `SampleLevel` с фильтрацией, `uv = worldPos.xz / size` | на краях смешиваются состояния; работает только при начале карты в 0,0 | `Load` точной клетки, учтено начало карты |
| «Рост» = канал `b` как дробь | не совпадает с форматом клетки | рост и культура берутся из битов клетки, стадия созревания — по культуре |
| Append-буфер на один чанк, перезапуск для каждого чанка | для карты 1 км² нужны сотни компонентов, сотни запусков и отрисовок | один запуск на все видимые чанки и один вызов отрисовки на культуру |
| `Append` без контроля переполнения | при густом поле запись за край буфера | счётчик `InterlockedAdd` с проверкой ёмкости и `min` в аргументах |
| Матрица 4×4 на стебель (72 байта) | лишняя память и полоса пропускания | 32 байта, матрица строится в вершинном шейдере |
| `CalculateFrustumPlanes(cam)` каждый кадр | мусор для сборщика каждый кадр | версия без выделения памяти |
| `CopyCount` в аргументы | при переполнении число больше, чем записано | `WriteArgs` пишет `min(счётчик, ёмкость)` |

## Цифры

- **Кочки на клетку** 0.5 м: 1, 2 или 4, то есть 4, 8 или 16 кочек на м². В кочке 4–7 стеблей.
- **На чанк** при 2 кочках на клетку: 8192 потока.
- **Весь кадр** при 192 видимых чанках: около 1,6 млн потоков отбора, это доли миллисекунды на современной видеокарте.
- **Дальность.** После 45 м кочек остаётся всё меньше, на краю дальности (160 м) — 12%, а оставшиеся шире, поэтому поле не выглядит «лысым».
- **Буфер:** 262 144 кочки на культуру × 32 байта = 8 МБ на культуру.
- **Телефоны** без compute-шейдеров (старый OpenGL ES 3.0): растения выключаются с предупреждением. Metal (iPhone) и Vulkan поддерживаются.

## Как подключить

1. На сцене уже есть `FieldManager` (шаг 1).
2. Пустой объект → `CropRenderer`: поле Culling = `CropCulling.compute`; список культур — культура, материал на шейдере `FarmSim/CropInstanced`, высота, ширина.
   - Меш можно не указывать, тогда соберётся простая кочка (`CropMeshFactory`).
3. Материал: текстура листа с альфой. Можно белую — тогда цвет берётся из Young/Ripe Color.

## Что проверено

- Логика «какие чанки засеяны» — тест `CropChunkIndexTests` (`dotnet test Tools/FieldTests`).
- Все 3 ядра compute-шейдера и все 3 прохода шейдера растений собираются компилятором HLSL. Для шейдера растений вместо URP подставлялись заглушки.
- В самом Unity не запускалось: его здесь нет.
- Та же идея (растение само читает свою клетку из карты поля) работает в браузерном показе шага 1.
